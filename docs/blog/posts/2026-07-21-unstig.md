# Unstig: An Unofficial STIG Checklist

[DISA STIGs](https://public.cyber.mil/stigs/) are the official hardening baselines used across DoD systems, but they're heavy: hundreds of controls, compliance scanners, and paperwork that don't make sense for a homelab or small VPS. This post is my "unstig" - the handful of STIG-inspired controls I actually apply to harden a Linux box without the full compliance overhead.

<!-- more -->

## SELinux
SELinux enforces mandatory access control so that even a compromised process is confined to what its policy allows, rather than whatever the running user can do.

Check the current mode:
``` sh
getenforce
```

Set it to enforcing immediately:
``` sh
setenforce 1
```

Make it persistent by editing `/etc/selinux/config`:
``` title="/etc/selinux/config"
SELINUX=enforcing
SELINUXTYPE=targeted
```

If something gets blocked, don't just disable SELinux - check the audit log and either fix the file context or write a policy exception:
``` sh
ausearch -m avc -ts recent
audit2allow -a
```

## Partition Hardening
Splitting a system into separate partitions/mounts lets you apply mount options that limit what each area of the filesystem can do. The idea: `/tmp`, `/var`, and similar writable-by-anyone or write-heavy paths should never be allowed to execute code or hold device nodes.

Example `/etc/fstab` entries:
``` title="/etc/fstab"
/dev/mapper/vg-tmp   /tmp   ext4   defaults,nodev,nosuid,noexec  0 2
/dev/mapper/vg-var   /var   ext4   defaults,nodev                0 2
/dev/mapper/vg-home  /home  ext4   defaults,nodev,nosuid         0 2
```

- `noexec` - blocks executing binaries from that mount (kills a common `/tmp` drop-and-run pattern)
- `nosuid` - ignores setuid/setgid bits, so nothing can escalate privileges from that mount
- `nodev` - ignores device files, so a mount can't be used to access hardware directly

Remount to apply without a reboot:
``` sh
mount -o remount /tmp
```

If a partition wasn't split out at install time, a bind mount is a lower-effort alternative:
``` title="/etc/fstab"
/tmp  /tmp  none  bind,noexec,nosuid,nodev  0 0
```

## Other Quick Wins

### SSH
``` title="/etc/ssh/sshd_config"
PermitRootLogin no
PasswordAuthentication no
X11Forwarding no
```

### Firewall
Default deny inbound, only open what's needed:
``` sh
firewall-cmd --set-default-zone=drop
firewall-cmd --permanent --add-service=ssh
firewall-cmd --reload
```

### Auditd
Keep a record of security-relevant events (STIG baselines lean heavily on this):
``` sh
systemctl enable --now auditd
auditctl -w /etc/passwd -p wa -k passwd_changes
```

### Kernel sysctl
``` title="/etc/sysctl.d/99-hardening.conf"
kernel.kptr_restrict = 2
kernel.dmesg_restrict = 1
kernel.yama.ptrace_scope = 1
net.ipv4.conf.all.rp_filter = 1
net.ipv4.tcp_syncookies = 1
```

### Unattended upgrades
Keep security patches flowing without babysitting every box - `unattended-upgrades` on Debian/Ubuntu or `dnf-automatic` on RHEL-likes.

## Why "Unstig"
None of this is a substitute for a real STIG if you actually need one for compliance - there's no scanner, no POA&M, no checklist to sign off on. It's just the short list of controls I've found give the most security benefit for the least ongoing maintenance burden on personal infrastructure.
